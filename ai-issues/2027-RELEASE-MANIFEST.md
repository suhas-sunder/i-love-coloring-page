## Acceptance record for each candidate
- Exact predecessor and head SHA, reviewed branch and draft PR, immutable preview at same SHA, source-image/approved-manifest policy.
- Diff and count of added, removed, changed canonicals; URL Inspection and sitemaps/image-sitemap deltas; no arbitrary mass indexable page dump.
- Typecheck, build, release quality gate, relevant semantic/unit tests, representative Chromium/WebKit screenshot QA (360, 390, 768, 1280, 1440), real print/download file checks, canonical/image crawl/accessibility, CLS/performance.
- The owner's October 14 **first-filled-ad suppresses all placeholders** workaround is preserved; no overlay, tap-jacking, or ad-interference risk. Preview analytics/ad isolation verified.
- Current GSC Web vs Google Image vs Bing data scopes and availability noted; no invented SEO impact or revenue. Cool-off and evaluation period recorded.
- Owner's explicit approval of **exact PR and SHA**, no implicit approval. Only after approval and all gates PASS may main be merged; then confirm actual production Netlify deployment and live functional/ad/indexability checks.
- If any critical gate fails: **HOLD / NO RELEASE**, preserve candidate and continue independent work; never push a partial/stale/mass package as a formality.

## Logging rules
Do not fill in fabricated SHAs, previews, PASS flags or approvals. A release's state transitions must be append-only in review notes: CANDIDATE → TESTING → OWNER REVIEW → APPROVED → RELEASED + VERIFIED, or HOLD/ROLLED BACK. Each actual release should record post-deploy owner-safe metrics and rollback commit.
